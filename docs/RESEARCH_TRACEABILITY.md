# Research-to-design traceability

This prototype translates recurring themes from six qualitative interviews into testable product behavior. The sample is exploratory and should not be treated as market-wide statistical evidence.

| Interview theme | Prototype response |
|---|---|
| Users become attached to a specific character, not a platform feature | Five authored character cores, each with an independent journey and identity continuity |
| Strong connection often begins through story, conflict, or being understood | Conflict-based opening chapter before long-term chat |
| Pure AI chat becomes repetitive and places all narrative work on the user | Official themes, character-initiated event, generated shared scene |
| Fixed story choices do not represent the user's actual reaction | Free text remains available alongside intent suggestions |
| OOC and model personality drift destroy trust | Character-specific conflicts, boundaries, refusal styles, and scene constraints |
| Users want the character to have a life outside the conversation | Home status and character-initiated events tied to each person’s work or travel |
| Users dislike long, ornate, low-information replies | Short multi-message chat responses |
| Users differ in creative effort from moment to moment | One natural-language scene input supports one sentence or a detailed paragraph |
| Memory loss damages the relationship | Visible Echoes timeline with edit, delete, source, and export concepts |
| A single affection number does not explain a relationship | Natural-language relationship summary and unresolved issues |
| Relationship wording can be mistaken for mutual intimacy | Separate character-to-player state, player-expression signals, and explicit mutual agreements |
| Characters should not possess omniscient context | Source-linked knowledge with confidence and per-character `knownBy` attribution |
| Users want control over long-running co-created stories | Recoverable archive snapshots and branch-isolated state |
| Daily conversation and shared activities can build connection | EchoLink private/group messages, character moments, asynchronous invitations, and promise follow-up |
| Users notice whether a reply actually responds to them | Character-specific offline replies use visible message content, memory, current relationship, and channel context |
| Voice and calls can feel more immediate than text | Simulated voice messages and explicit call availability states test narrative value without a paid animation or fake media claim |
| Personality or memory discontinuity can feel like losing the character | EchoLink history, contact permissions, commitments, and pulse state are exported and restored with the branch |
| Users want editable memory without erasing character agency | Facts/events/promises can be corrected; character judgements and reflections are not directly rewritten |
| Daily chores and message quotas interrupt emotional immersion | No coins, stamina, streaks, mandatory tasks, or message limit |
| Users recognize the relationship is virtual but still value it | The UI respects emotional investment without claiming AI consciousness |

## What remains a design hypothesis

- Whether one opening story is enough to create attachment.
- Whether five initial choices improve agency without encouraging shallow catalogue browsing.
- Whether users understand selection as the start of an acquaintance rather than a romance.
- The optimal length and media format for the opening.
- How often a character should initiate events.
- How much memory transparency users want.
- Whether the eleven relationship dimensions should be reduced after usability testing.
- Whether users understand that a romantic or sexual signal is not mutual agreement or consent.
- Whether source/confidence labels improve trust enough to justify their complexity.
- Whether branch rewind changes choices in productive or consequence-avoiding ways.
- Whether the three continuity modes preserve character identity clearly enough.
- Whether five EchoLink tabs make communication state legible without feeling like a conventional phone app.
- Whether communication pulses and observer intervals invite unwanted min-maxing.
- Whether private intent confirmation improves interpretation of ambiguous free text.
- Which contact and channel permissions users perceive as meaningful relationship development.
- Whether users prefer main-timeline selection before or after a generated scene.
- Whether heavy co-creation users need separate controls or embedded director notes.
- Whether Zhou Tang's boundary-led cooperation and Wen Sheng's expression-led co-creation are experienced as genuinely distinct relationship modes rather than cosmetic roster expansion.
